**Default advice: use the existing one.** Only write a new utility when the existing one actually can't do what you need, and you can name the gap, such as wrong timezone handling, a missing format, or no parsing. Two utilities that do almost the same thing tend to drift apart, and then you get bugs where one part of the code uses UTC and another uses local time.

**For this repo specifically:** two call sites don't justify a new shared helper. Keep calling `datetime` directly. One thing to keep consistent: use timezone-aware UTC like `log_team_message.py` does. `date.today()` uses the local timezone, so near midnight it can give a different date than the UTC-based meeting IDs. If you end up formatting dates in a third or fourth place, a small helper in `scripts/` would then make sense.
