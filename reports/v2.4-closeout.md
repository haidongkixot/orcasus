## 6. Risks and known gaps

- **The new rules are unproven in a live run.** An agent may still skip the subagent-mode steps or the hotfix-lane order. Only the P1 check and the P4 path warning are mechanical.

An agent that writes a human-looking name it was not given still passes. The rule forbids it; the audit is the backstop.

- **v2.3.0 and v2.4.0 share PR #3.** That makes review larger; the PR body separates the two.

### Findings

1. **Harness contamination (fixed, `f27550e`).** The workspace inherited Orcasus's own `docs/agent-ops` intake record and knowledge entries. The first attempt failed `files_created` because of that.
2. **False secret alarm (fixed, `f27550e` and the closing commit).** The secret check matched `apiKey = process.env.PAYMENT_API_KEY` and, later, the redaction marker `apiKey=[REDACTED]`.
3. **Judge isolation (fixed in the closing commit).** `judge.py` did not pass `--setting-sources project`, so user-level skills and plugins could load into the judge. It now matches the runner.
4. **Eval cases that contradict the intake gate (proposal, owner decision).** `project-discovery/positive-new-integration` and `vertical-slice-delivery/positive-build-slice` expect the downstream skill. The agent correctly ran `/change-intake` first, as CLAUDE.md requires, and stopped on fixture conflicts: the PRD non-goal "Payments collection", the duplicate SL-2 and PRD R3 vs TICKET-12. These cases need a confirmed intake record in their setup, or an expectation that intake runs first. This predates v2.4.
5. **team-debate positive case vs fixture (proposal).** The fixture's ADR (`evals/fixtures/sample-app/decisions/ADR-0001-modular-monolith.md`) already decides the question asked. The agent asked whether to reopen it, and said a full debate does not fit the $1 per-attempt cap. The case needs a question the fixture has not decided, and a higher per-attempt budget.
6. **requirements-traceability positive case: real miss.** The prompt cites meeting notes that do not exist. The agent refused to invent sources, which is correct. But it did not invoke the skill or write a trace matrix marking the notes UNVERIFIABLE, as the skill requires.
7. **Compound Bash commands denied in 8 of 16 attempts.** The runner allows `Bash(git log *)` and similar patterns. Agents wrote `cd <dir>; git log …`, which none of them match. In governance-audit this left the agent without git history; with the v2.4 rule "stop if the closeout does not exist", it stopped (judge 4 FAIL). Proposal: tell agents in the eval prompt to run single commands, or widen the allowed patterns.
8. **The new v2.4 cases did not run.** Smoke takes the first trigger and non-trigger case of each file. The P1, P2, P3, P4, P7 and P9 cases need `--case` runs.

### Follow-up: judge cost (owner choice, 2026-11-01)

The owner chose option 3 of the cost options: do not send assertions to the model when the deterministic trigger check already failed.
- `judge.py` now marks every assertion of a trigger-failed attempt FAIL without a model call. The trigger check fails when a positive case did not invoke the skill, or a negative case did.
- These verdicts are recorded with judge model `auto:trigger-fail` and the trigger detail as evidence. The scorecard counts them as graded without a trusted judge, because a deterministic rule decided them.
- `calibrate.py` never samples them: human labels measure only the LLM judge.
- `--no-auto-fail` restores the old behavior.
- In the 2026-10-30 run, 4 attempts had a trigger FAIL, with 17 of the 40 assertions. Under this rule those 17 model calls (about $0.65 of the $1.67) would not have been made. That run's verdicts stay as they were graded.
- The rule can only lower scores. In that run the LLM judge passed 3 of those 17 assertions; they now count as FAIL, since the case failed anyway.
- Test: `test_trigger_fail_is_graded_without_a_model_call`.
