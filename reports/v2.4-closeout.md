## 6. Risks and known gaps

- **The new rules are unproven in a live run.** An agent may still skip the subagent-mode steps or the hotfix-lane order. Only the P1 check and the P4 path warning are mechanical.
- **The agent-name list in the P1 check is a heuristic.** It covers `claude`, `agent`, `assistant`, `ai`, `lead`, `orchestrator`, `main agent`, `subagent` and the role names in `.claude/agents/`. An agent that writes a human-looking name it was not given still passes. The rule forbids it; the audit is the backstop.
- **The P4 warning is noisy across repos.** It warns about any backtick path under the record folders. Records that quote paths from another repository will see false warnings (3 appeared on tbagri-web).
- **v2.3.0 and v2.4.0 share PR #3.** That makes review larger; the PR body separates the two.

### Follow-up: judge cost (owner choice, 2026-11-01)

The owner chose option 3 of the cost options: do not send assertions to the model when the deterministic trigger check already failed.
- `judge.py` now marks every assertion of a trigger-failed attempt FAIL without a model call. The trigger check fails when a positive case did not invoke the skill, or a negative case did.
- These verdicts are recorded with judge model `auto:trigger-fail` and the trigger detail as evidence. The scorecard counts them as graded without a trusted judge, because a deterministic rule decided them.
- `calibrate.py` never samples them: human labels measure only the LLM judge.
- `--no-auto-fail` restores the old behavior.
- In the 2026-10-30 run, 4 attempts had a trigger FAIL, with 17 of the 43 judged assertions (corrected from "40"). Under this rule those 17 model calls (about $0.65 of the $1.67) would not have been made. That run's verdicts stay as they were graded.
- The rule can only lower scores. In that run the LLM judge passed 3 of those 17 assertions; they now count as FAIL, since the case failed anyway.
- Test: `test_trigger_fail_is_graded_without_a_model_call`.
